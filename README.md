# scene-flow gallery

A static Next.js site that lists short videos made with scene-flow. Each video has its own page, and the grid can be filtered by theme. The site reads a JSON manifest at build time. Videos and posters are served from a separate media host.

## Requirements

- Node.js 24. The minimum is 20.18, because the site uses `URL.parse`.
- pnpm 11.22.0, the version in the `packageManager` field of `package.json`.
- ffmpeg and ffprobe, with the libx264, libwebp, and aac encoders. Needed only for `scripts/prepare-video.sh`.
- Wrangler, needed only for uploads to R2.

## Local development

```sh
pnpm install
pnpm dev        # dev server, URL printed on start
pnpm lint
pnpm test
pnpm build      # writes the static site to out/
pnpm exec playwright install chromium
pnpm test:e2e   # builds with the fixture manifest and serves out/ on port 4173
```

To preview the fixture videos:

```sh
VIDEOS_MANIFEST=tests/fixtures/videos.json pnpm dev
VIDEOS_MANIFEST=tests/fixtures/videos.json pnpm build && pnpm exec serve out
```

## Environment variables

| Variable                 | Used by                                | Default                       | Purpose                                                                                                                                               |
| ------------------------ | -------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_MEDIA_HOST` | Site build, `scripts/prepare-video.sh` | `media.example.com`           | Host of the video and poster URLs. The site reads it at build time and bakes it into the static output. Manifest URL hostnames must equal this value. |
| `NEXT_PUBLIC_SITE_URL`   | Site build                             | `https://gallery.example.com` | Site origin used in metadata, `robots.txt`, and the sitemap. The site reads it at build time and bakes it into the static output.                     |
| `VIDEOS_MANIFEST`        | Site build and dev server              | `content/videos.json`         | Path to the manifest, relative to the current directory.                                                                                              |
| `VERSION`                | `scripts/prepare-video.sh` only        | `1`                           | Positive integer. Sets the `-v<VERSION>` suffix in file names and URLs. Use `2` to publish a changed video under new keys.                            |

## Add a video

1. Render the video with scene-flow: `<scene-flow render command>`. The input must be 9:16, for example 576x1024. A file whose only rotation is a legacy `rotate` tag is rejected, because ffmpeg does not apply that tag.

2. Create the MP4 and the poster. Choose a slug made of lowercase letters, digits, and hyphens. Choose a poster time in seconds that is less than the video length:

   ```sh
   scripts/prepare-video.sh "<input>" <slug> <poster-seconds> > /tmp/<slug>.json
   ```

   The script writes `media/<slug>-v1.mp4` and `media/<slug>-v1.webp` in this repository. It prints the manifest entry as JSON to `/tmp/<slug>.json`. Progress messages go to stderr.

3. Upload the MP4. `<bucket>` is your R2 bucket name. The repository does not store it:

   ```sh
   wrangler r2 object put <bucket>/v/<slug>-v1.mp4 --file media/<slug>-v1.mp4 --content-type video/mp4 --cache-control "public, max-age=31536000, immutable" --remote
   ```

   Wrangler 4.129.1 rejects files larger than 300 MiB.

4. Upload the poster:

   ```sh
   wrangler r2 object put <bucket>/v/<slug>-v1.webp --file media/<slug>-v1.webp --content-type image/webp --cache-control "public, max-age=31536000, immutable" --remote
   ```

5. Open `/tmp/<slug>.json`. Replace every `TODO` value: `title`, `script`, and `creator.name`. The build accepts `TODO` as text, so check this by hand. Check `theme`, `lang`, and `sources` too. Then append the entry to the array in `content/videos.json`.

6. Run `pnpm build`. An invalid manifest fails the build (see Manifest rules).

7. Commit the manifest change. `media/` is ignored by Git.

   ```sh
   git add content/videos.json
   git commit -m "Add <slug> video"
   ```

To replace a file that was already uploaded, run `VERSION=2 scripts/prepare-video.sh ...` and upload the `-v2` files. The uploads send `Cache-Control: public, max-age=31536000, immutable`, so caches may keep serving an old file at the same key. Then update the URLs in the manifest.

If the voice is generated by TTS, record the provider in `sources.voice` and the attribution in `sources.notes`. The terms of the TTS providers were not verified for this repository.

## Credentials

Authenticate Wrangler with one of these methods:

- Run `wrangler login`. It opens a browser login page.
- Export the token for the current shell session: `export CLOUDFLARE_API_TOKEN=<api-token>`.

Never commit tokens. Nothing in this repository reads them.

## Cloudflare setup

The maintainer owns this setup.

1. Create an R2 bucket. In the bucket settings, under Public access, open Custom Domains and connect the host from `NEXT_PUBLIC_MEDIA_HOST`.

2. Create a Pages project from the GitHub repository. Use these build settings:
   - Build command: `pnpm build`
   - Build output directory: `out`. This is the directory Next.js writes for a static export, and it matches Cloudflare's Next.js (Static HTML Export) preset.
   - Environment variables: `NEXT_PUBLIC_MEDIA_HOST`, `NEXT_PUBLIC_SITE_URL`, and `NODE_VERSION`. Set `NODE_VERSION` to `24`, matching CI. The Pages build image reads this variable. The value was not tested on Pages.

3. Check which pnpm version the first Pages build uses. It should be 11.22.0. Pages detection of the version from `packageManager` was not verified.

4. Open item before launch: `next.config.ts` sets `trailingSlash: true`. Confirm that the Pages site serves `/v/<slug>/` as expected. This was not verified.

## Manifest rules

`content/videos.json` is a JSON array of entries.

| Field                      | Rule                                                     |
| -------------------------- | -------------------------------------------------------- |
| `slug`                     | Matches `^[a-z0-9-]+$`. Unique across entries.           |
| `title`                    | Non-blank text.                                          |
| `theme`                    | `dark`, `paper`, or `world3d`.                           |
| `videoUrl`                 | Valid URL. Its hostname equals `NEXT_PUBLIC_MEDIA_HOST`. |
| `posterUrl`                | Valid URL. Its hostname equals `NEXT_PUBLIC_MEDIA_HOST`. |
| `durationSec`              | Positive number.                                         |
| `publishedAt`              | ISO date, `YYYY-MM-DD`.                                  |
| `lang`                     | Valid BCP 47 language tag.                               |
| `script`                   | Non-blank text.                                          |
| `creator.name`             | Non-empty text.                                          |
| `creator.url`              | Optional. Valid URL.                                     |
| `sources.voice`            | `self-recorded`, `tts-api`, or `vieneu-tts`.             |
| `sources.screenRecordings` | Boolean.                                                 |
| `sources.notes`            | Optional text.                                           |

An invalid manifest fails `pnpm build`. The error names the entry index and the field, for example `videos[0].title: must not be blank`.

An empty manifest (`[]`) builds. The home page shows `No videos yet`. A static export needs at least one `/v/[slug]` route, so the build also writes `out/v/_none/`. That route is not a video. Its page has a `noindex` robots meta tag. The file is static, so a host may serve it with HTTP 200. Cloudflare Pages behavior for this route was not tested.

## CI

`.github/workflows/ci.yml` runs on pull requests and on pushes to `main`. It uses Node 24 and runs `pnpm install --frozen-lockfile`. Then it runs lint, unit tests, a production build, and a build with `tests/fixtures/videos.json`. It installs Chromium and runs the Playwright end-to-end tests. If the job fails, it uploads the Playwright report as an artifact.

## Placeholder domains

`media.example.com` and `gallery.example.com` are placeholders. They appear in `.env.example`, in the defaults above, and in the fixture manifest for `media.example.com`. Keep them until the real domains exist. Then update the environment variables, the Pages settings, and the manifest URLs.
